# 离职补偿金计算器 · 技术方案

> 这份文档解决的问题：**三个月后你回来看这个项目，怎么在 10 分钟内想起该怎么改。**

---

## 一、产品定位

### 用户是谁

| 画像 | 场景 | 核心诉求 | 对页面的要求 |
|---|---|---|---|
| 刚被通知走人 | HR 说「下周不用来了」 | 我该拿多少？ | 立刻出数，不需要注册 |
| 正在谈赔偿 | 手里有份协议，数字不确定 | 这个数对不对？ | 拆解每一项，能拿去对账 |
| 已经签了 | 事后觉得被坑 | 还能补救吗？ | 仲裁时效、证据清单 |

### 设计原则

1. **3 秒出结论** —— 打开页面就有结果，不是空表单
2. **每个数字都能溯源** —— 结论旁边就是法条
3. **说人话** —— 「满 6 个月不满 1 年按 1 年算」而不是「依第四十七条第一款」
4. **不制造恐慌** —— 不说「你被坑了」，说「按法条应该是 X，实际给了 Y，差额 Z」

```
│  ui/         │ │  core/       │ │ integrations/│

│  result      │ │  compensation│ │  analytics   │
│  format      │ │              │ │  api         │
│  chart       │ │  （纯函数）   │ │  auth        │
└──────┬───────┘ └──────┬───────┘ └──────────────┘
       │                │
       └────────┬───────┘
                ▼
        ┌──────────────┐
        │  data/       │  情形规则 / 社平工资 / FAQ
        │  config.js   │  站点 / 广告 / 开关
        └──────────────┘
```

### 分层铁律

| 层 | 可以依赖 | 禁止依赖 | 原因 |
|---|---|---|---|
| `data/` | 无 | DOM、core | 以后可能从接口下发 |
| `core/` | `data/` | DOM、ui | 要能搬到 Node/后端复用，要能单测 |
| `ui/` | `core/`、`data/`、`format` | 直接算法 | UI 只做「对象 → 屏幕」映射 |
| `integrations/` | 无 | 业务逻辑 | 接第三方的部分要能整体替换 |
| `app.js` | 全部 | — | 唯一的胶水层 |

**为什么坚持不用 ES Module**：`file://` 下 `import` 会被 CORS 拦死，
用户双击 HTML 打不开。全站用 IIFE + `window.APP` 命名空间，牺牲一点优雅换取零门槛。

## 三、核心算法

### 3.1 工作年限 → N

```
满整年数 y = 从入职日逐年推进，直到再加一年就超过离职日

剩余部分判定（关键，最容易错）：
  剩余 ≥ 6 个月  → N = y + 1
  剩余 > 0       → N = y + 0.5
  剩余 = 0 且 y>0 → N = y
  剩余 = 0 且 y=0 → N = 0.5   ← 入职当天离职也是半个月，不是 0
```

**必须用「周年日推进」而不是「月差相减」**：

```js
// ✅ 正确
while (addYears(start, years + 1) <= end) years++;

// ❌ 错误：2 月 29 日入职会被算错一天
years = end.getFullYear() - start.getFullYear();
```

### 3.2 三倍社平封顶

```
cap  = 当地上年度职工月平均工资 × 3
base = 月工资 > cap ? cap : 月工资
年限 = (月工资 > cap && N > 12) ? 12 : N
```

注意：**年限 12 年上限只在被三倍封顶时才生效**。
月薪没超 3 倍社平，工作 20 年就是 20 个月，不封顶。

### 3.3 代通知金

```
needsNoticePay = scenario.plusOne && !noticed30
noticePay      = needsNoticePay ? base : 0
```

`plusOne` 只对第 40 条的三种情形为 `true`：
医疗期满、不能胜任、客观情况重大变化。

### 3.4 未休年假

```
日工资     = base / 21.75
额外补偿   = 未休天数 × 日工资 × 200%
```

法条表述是「按日工资收入的 300% 支付」，其中 100% 是正常工作期间已发的工资，
所以用人单位**还需额外支付 200%**。本工具按「额外应付」口径计算，与仲裁实践一致。

## 四、扩展点：十个功能的落点

每个都写清楚「改哪个文件、加什么函数、UI 放哪」，照着做就行。

### 4.1 策略对比（协商 N vs 仲裁 2N）

**改哪里**：`core/compensation.js` 已有 `compareStrategies()`，返回两种情形的金额。
**加什么**：`ui/result.js` 里加一个 `<div class="compare">`，画两组数字 + 差额。
**注意**：文案必须中立，不能写成「建议你去仲裁」。仲裁有败诉风险和时间成本，工具不该替用户做决定。

### 4.2 补偿金个税

**规则**：财税〔2018〕164 号 —— 当地上年职工平均工资 3 倍以内的部分免征个税，
超过部分单独适用综合所得税率表（不并入当年综合所得）。

**改哪里**：`core/compensation.js` 新增 `calcTax(result)`。
**数据**：`data/severance-rules.js` 加一个 `taxBrackets` 数组（7 级超额累进）。
**UI**：结果区加一行「预计个税」。

### 4.3 加班费

**规则**：工作日 1.5 倍、休息日 2 倍、法定节假日 3 倍，基数按正常工作时间工资。
**改哪里**：新建 `core/overtime.js`，输入「近 2 年加班时长」。
**难点**：举证责任。劳动者只需初步举证，用人单位掌握考勤记录却不提供的，承担不利后果。
**UI**：建议做成独立 Tab，不要塞进主表单。

### 4.4 未签书面合同二倍工资

**规则**：用工满 1 个月不满 1 年未签书面合同，每月支付 2 倍工资，最多 11 个月。
**改哪里**：`core/compensation.js` 新增 `calcDoubleWage()`，输入「是否有书面合同」「入职日期」。
**注意**：仲裁时效从「应当签订合同之日起满 1 年」起算，容易过期，要在 UI 上提示。

### 4.5 城市社平工资自动填充

**改哪里**：`integrations/api.js` 已有 `endpoints.cityWage` 桩位。
**后端**：`GET /config/city-wage` 返回 `{ list: [{ city, wage }] }`。
**降级**：`fallbackToLocal: true` 时用 `data/severance-rules.js` 里的内置值。
**为什么需要**：社平工资每年 6-7 月更新，写死在代码里迟早过期。

### 4.6 导出 PDF 报告

**方案 A（推荐）**：`window.print()` + 专门的 `@media print` 样式表。
零依赖、体积为 0、用户还能选「另存为 PDF」。
**方案 B**：html2pdf.js（约 100KB）。**不建议** —— 为了一个低频功能拖慢首屏不值。
**改哪里**：`assets/css/print.css` 新建，`APP.FEATURES.exportPdf = true`。

### 4.7 分享长图

**方案**：Canvas 手绘（约 80 行），画一个 750×1000 的卡片：
标题 + 金额 + 三个拆解项 + 二维码。
**改哪里**：新建 `ui/share-card.js`。
**钩子**：`navigator.share()` 优先，不支持时降级为下载 PNG。

### 4.8 律师咨询线索（CPA 变现）

这是这个站**最值钱的变现方式**，比广告高一个数量级。

**改哪里**：`integrations/api.js` 已有 `endpoints.leadSubmit`。
**流程**：结果区底部加「免费咨询律师」按钮 → 弹表单（手机号 + 简述）→ 提交 → 转给律所。
**计价**：法律咨询类线索单价 ¥30–150/条，取决于地区和案件类型。
**合规**：必须明示「提交即同意将信息提供给合作律所」，并给隐私政策链接。

### 4.9 云端保存方案

**改哪里**：`integrations/api.js` 的 `savePlan` / `getPlan`，`integrations/auth.js` 的登录。
**为什么值得做**：用户算完可能想「过两天再来看」，保存后可以发提醒（邮件/短信），
这是唯一能把「一次性流量」变成「可触达用户」的手段。

### 4.10 多语言

**价值低**：这个需求是强中国法律场景，海外没有对应法条。
**建议**：不做。把精力放在「劳动合同法修订跟进」上更值。

## 五、SEO 策略

### 5.1 页面结构

只有一页，但要做足：

- `<title>` 覆盖主词 + 修饰词：「离职补偿金计算器｜被辞退能拿多少钱？N、N+1、2N 一键算清」
- `description` 里塞进 4-5 个长尾词，控制 155 字符内
- `WebApplication` 结构化数据（静态写在 HTML 里）
- `FAQPage` 结构化数据（JS 从 `data/faq.js` 自动生成，改 FAQ 不用改 HTML）
- H1 只有一个，H2 按板块分

### 5.2 内容矩阵

单页工具站的天花板很低。真正的流量来自：

```
首页（工具）
  ├── /wenda/  问答页：每个长尾词一篇 800-1500 字
  ├── /anli/   案例页：真实（脱敏）仲裁案例拆解
  └── /tiaowen/ 法条页：每条法条一页，内链回工具
```

每篇文章底部放「用计算器算一下你的情况」→ 导流回首页。
详见 `docs/关键词矩阵.md`。

### 5.3 技术 SEO

- 全部静态，无 JS 也能看到主体内容（工具本身需要 JS，但 FAQ 和文案是 HTML）
- 首屏无阻塞资源，CSS 内联关键部分（后续可优化）
- 移动端优先，`viewport-fit=cover` 适配刘海屏
- 没有 `robots.txt` 限制，记得提交 sitemap

## 六、性能与成本

| 指标 | 当前 | 说明 |
|---|---|---|
| 首屏 HTML | ~18 KB | 未压缩 |
| CSS 合计 | ~38 KB | 4 个文件 |
| JS 合计 | ~62 KB | 14 个文件，全部同步加载 |
| 第三方依赖 | **0** | 不用框架、不用图表库、不用 UI 库 |
| 部署成本 | **0 元** | GitHub Pages / Cloudflare Pages / Vercel 免费额度足够 |

对比：如果用 Vue + Element Plus + ECharts，光是依赖就 800KB+，
首屏时间从 0.3s 变成 2s，而用户得到的体验没有任何提升。

**优化的下一步**（如果流量真的起来了）：
1. JS 合并成一个文件（14 个请求 → 1 个）
2. 开启 gzip/brotli（CDN 自动做）
3. CSS 关键部分内联，其余异步加载

| 招聘平台广告 | CPC ¥0.5–3 | 需要流量 | ★★☆ |
| 通用联盟广告（AdSense 等） | CPC ¥0.3–2 | 需要备案+流量 | ★☆☆ 保底 |
| 付费导出报告 | ¥9.9/次 | 需要支付通道 | ★☆☆ 转化率低 |

### 广告位设计

| 位置 | 尺寸 | 说明 |
|---|---|---|
| `result-inline` | 结果区底部 | **转化最高**，用户刚看完数字，情绪最强 |
| `content-banner` | 计算区与 FAQ 之间 | 常规展示位 |
| `faq-banner` | FAQ 底部 | 阅读完的人意向更明确 |

**不要**把广告放在计算按钮和结果之间 —— 会被判诱导点击，而且真的会掉转化。

## 十、已知坑

### 坑 1：社平工资每年变

每年 6-7 月各地人社局公布上年度社平工资，**必须更新**。
如果忘了更新，用户算出来的封顶金额是错的，这属于实质性错误。

**解法**：`APP.API.endpoints.cityWage` 接一个远程配置，或者至少在 `data/severance-rules.js`
里把数据日期标出来，首页提示「数据截至 2024 年」。

### 坑 2：2N 是否受三倍封顶限制，各地裁判口径不一

部分地区认为 2N 也受第 47 条限制（含三倍封顶和 12 年上限），
部分地区认为赔偿金不适用封顶。

**当前实现**：统一按封顶处理，并在提示里写明「部分地区有不同口径，以当地裁判为准」。

### 坑 3：代通知金的基数

法条写的是「额外支付劳动者**一个月工资**」，实践中一般按**上一个月工资**，
而经济补偿的基数是**前 12 个月平均工资**。两者可能不同。

**当前实现**：都用 12 个月平均，简化处理。如果要做精确版，
在 `core/compensation.js` 里把 `noticePay` 改成独立的 `lastMonthWage` 入参。

### 坑 4：`input[type=date]` 在 iOS Safari 上宽度会跳

**已处理**：`.input-date { width: 100%; -webkit-appearance: none; min-height: 48px; }`

### 坑 5：超长页面截图丢元素

调试时用 headless Chrome 截整页，如果页面有 CSS 动画，`captureBeyondViewport`
会出现元素不渲染的情况。**解法**：截图前注入 `* { animation: none !important }`。
（这只影响调试工具，不影响真实用户。）
