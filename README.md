# 离职补偿金计算器

> 被辞退，能拿多少钱？填两个日期和一个工资，10 秒算清 **N / N+1 / 2N**，
> 附法条依据、三倍社平封顶判断和维权证据清单。

纯静态站点，双击 `index.html` 就能跑，不需要 npm、不需要构建、不需要服务器。

---

## 一、为什么做这个

搜索「经济补偿金怎么算」「被辞退能拿多少钱」的人，此刻正处在三种状态之一：

1. **刚被通知走人**，需要立刻知道该拿多少，好去谈
2. **正在签协议**，需要判断这个数对不对
3. **已经签了**，事后怀疑被少给了

这三种人有一个共同点：**极度焦虑、极度需要确定性**。
所以这个页面的设计目标不是「功能多」，而是 **3 秒内给出一个可信的数字，并解释它怎么来的**。

对应到产品决策：

| 决策 | 原因 |
|---|---|
| 打开即出结果（预填默认值并算一次） | 空白结果页会让 60% 的人直接走 |
| 工作年限做成实时展示条 | 用户边填边有反馈，建立信任 |
| 每个情形带「N / N+1 / 2N / 无补偿」角标 | 一眼看懂法律后果，胜过读 200 字描述 |
| 金额拆成「补偿 / 代通知金 / 年假」三行 | 谈判时可以直接照着念 |
| 法条依据默认折叠 | 需要的人点开，不需要的人不被法条吓跑 |
| 每条建议都带具体数字 | 「你应该争取 60,000 元」比「建议维权」有用一万倍 |

## 二、快速开始

```bash
# 方式一：直接双击
index.html

# 方式二：本地起个静态服务（推荐，避免 file:// 的个别限制）
npx serve .
# 或
python -m http.server 8080
```

打开后默认已算好一例（工作 5 年 8 个月、月薪 1 万、协商解除 → 6 个月 × 1 万 = 6 万），
改任意一个输入，右侧实时更新。

## 五、改代码前必看

### 1. 法条变了 → 只改 `data/severance-rules.js`

每个情形的 `multiple`（N 的倍数）、`plusOne`（有无代通知金）、`legal`（条文索引）
都在这个文件里。UI 和计算层都从这里读，改一处全站生效。

### 2. 计算逻辑在 `core/`，不碰 DOM

`core/service.js` 只做日期与年限，`core/compensation.js` 只做金额汇总。
两层都是纯函数，可以直接搬到 Node 或后端复用，也方便写测试。

### 3. 「口径」这件事最容易出错

三处必须保持一致（`core/service.js` 已统一）：

- `servicePeriod()` 算「几年几月几天」
- `compensationMonths()` 算折算后的 N
- 两者都用 **周年日推进法**，不是月差相减

> 举个例子：2024-02-29 入职、2025-03-01 离职。
> 月差法算出「1 年 0 天」，周年日法算出「1 年 1 天」。
> 口径不一致会让展示年限和计算年限打架，用户一眼就看出不对。

### 4. 开关都在 `config.js`

要接广告改 `APP.ADS`，要接埋点改 `APP.ANALYTICS`，
要实现新功能把 `APP.FEATURES` 里对应的开关从 `false` 改 `true` 再去补实现。
